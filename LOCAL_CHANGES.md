## Follow-ups / known limitations

- **Image downloader database is upstream-only (2026-06-27).** `databaseurl` now points at `WagicProject/wagic/releases/latest/download/CardImageLinks.csv`. That CSV indexes only upstream sets, so the **fast (indexed) download** covers upstream cards; any **fork-added set** (ECL, TLA, SOS, and other post-upstream content) is **not in the index** and falls back to the slow per-card Scryfall scrape — slower, and it can't fetch cards Scryfall won't map by multiverseid. To fully fix: publish our own `CardImageLinks.csv` (covering fork sets) as an asset on a **non-prerelease** fork release, then repoint `databaseurl` back at `Flounder1664/wagic`. CSV-generation tooling lives in the `wagic-tools` repo.
- **Draft mode is Windows-only so far (2026-07-10).** `feature/draft-mode` has never been built for or tested on Android this cycle — everything was verified via the WSL headless harness and the Windows deploy to `G:\Wagic-windows`. Before shipping to Android: an `ndk-build`/APK pass, and folding `packs/draft_booster.txt` (currently a loose Res file) into whatever resource zip Android actually reads, since loose-file resolution was only confirmed on the PC build. Sideboarding between games of the best-of-3 bracket is tracked separately as a future feature, not a bug — see GH issue [#28](https://github.com/Flounder1664/wagic/issues/28) (covers constructed/Quest too, not just draft).

## Diagnostic notes (2026-05-07)

Two separate S9 issues converged into the user's "broken" report:

1. **Internal app data corruption** (manifested as SIGSEGV in libgui's BufferQueue ~14s into launch). Same crash reproduced on `verified-android-2026-04-19` libmain.so, `wagic-v145-windows` tip, and the Phase 1 cherry-pick build. Fixed by `pm clear net.wagic.app`. Saves on the S9 SD card (UUID `0449-B4A1`) survived the clear.
2. **Outdated core.zip on S9 SD card** (54.8 MB vs PC's 55.5 MB). Caused features like quickplay to be missing. Fixed by pushing the PC's `core.zip` to `/storage/0449-B4A1/Android/data/net.wagic.app/files/Wagic/Res/Wagic-core-0255.zip`.
3. **Real code regression** in `7a32a6f30` (Apr 24): `SDL_JoystickEventState(SDL_ENABLE)` on Android causes SDL to pump non-touch input into the joystick event queue, starving real touch dispatch. RP5 was unaffected because its gamepad goes through Android's keysym path, not SDL's joystick API. Fix: scope the joystick-open block `#ifndef ANDROID` so PC keeps the Apr-24 gamepad code and Android falls back to pre-Apr-24 behavior.
