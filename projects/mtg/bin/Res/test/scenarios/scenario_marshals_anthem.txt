#Multikicker is GREEDY (MTGRules.cpp:544): it throws away your answer and kicks as many
#times as your mana pool can afford. That is why Apex Hawks took five counters last run -
#the pool had eight mana in it. So this board gives EXACTLY enough for one kick and has
#NO LANDS, so nothing extra can be tapped and greedy == what you intended.
#
#  APEX HAWKS ({2}{W}, multikicker {1}{W}) - the control, known good.
#     Six white. Base 3 + one kick 2 = 5; a second kick would need 7, so it cannot.
#     EXPECT: a 2/2 flier - the 1/1 body with exactly ONE +1/+1 counter.
#     If it takes more than one counter, the greedy loop is worse than understood.
#
#  MARSHAL'S ANTHEM ({2}{W}{W}, multikicker {1}{W}) - the suspect.
#     Six white. Base 4 + one kick 2 = 6; a second kick would need 8, so it cannot.
#     Two creatures in the graveyard.
#     EXPECT by the real card: exactly ONE of them returns to the battlefield.
#
#     This is the decisive one. kicked can now only be 1, so:
#       * one creature returns  -> multikicker was never the problem, the greedy payment
#                                  was, and Marshal's Anthem is fine
#       * NO target prompt      -> <upto:kicked> is resolving to 0
#       * prompt but nothing moves -> the moveto is at fault, not the count
#
#Six mana forces exactly ONE kick on EITHER card. The pool only funds one of them, so
#cast Apex Hawks, note the result, then RELAUNCH and cast Marshal's Anthem on a fresh pool.
